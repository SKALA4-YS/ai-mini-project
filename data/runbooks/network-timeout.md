# Runbook: 네트워크 타임아웃 대응 절차

## 대표 증상
시스템 간 호출이 응답을 받지 못하고 시간 초과로 끊긴다. 게이트웨이의 504 Gateway Timeout, upstream 연결 끊김, 패킷 손실, DNS 해석 실패, 외부 API 호출 타임아웃이 나타난다. 키워드: 타임아웃, 504, 패킷 손실, 네트워크 단절, upstream.

## 대응 절차
1. get_monitoring_status로 어떤 시스템 간 호출에서 타임아웃이 발생하는지 확인한다.
2. DNS 해석 실패, 방화벽/보안그룹 변경, 로드밸런서 헬스체크 실패 중 최근 변경 사항이 있었는지 점검한다.
3. 특정 리전/가용영역에서만 발생하면 해당 구간을 우회하는 라우팅으로 임시 전환한다.
4. 타임아웃 값이 너무 짧아 정상 응답도 실패로 처리되는 경우라면 임계값을 임시 상향해 2차 피해를 줄인다.
5. 정상화 후 네트워크 경로 기록을 남기고, 재발 방지를 위해 헬스체크 주기와 재시도 정책을 재검토한다.
